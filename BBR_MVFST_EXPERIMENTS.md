# BBR and mvfst extension

This extension prepares experiments that are absent from the current result
tree. It does not pool HTTP/3 and raw-QUIC outcomes.

## Safe sequence on Ubuntu

```bash
cd /home/ioio33/QUICbench
sudo -v

python3 scripts/run_bbr_mvfst_extension.py preflight --matrix all-missing
python3 scripts/run_bbr_mvfst_extension.py canary --matrix all-missing
./scripts/check_bbr_mvfst_extension.sh
```

Only after every canary manifest is valid and saturated:

```bash
python3 scripts/run_bbr_mvfst_extension.py full \
  --matrix all-missing \
  --trials 3
```

Run the command inside `tmux`; do not append `&`. The wrapper and worker keep
status files and resume already complete conditions.

## Matrices

`bbr-core` contains xquic-BBR and mvfst-BBR. `mvfst-cc` contains mvfst with
CUBIC, NewReno, and BBR. `all-missing` combines xquic-BBR with all three mvfst
CCs. Every matrix includes pacing on/off. The default policy suite is only the
realistic Neqo/Chromium matrix. The old fixed2/fixed10 suite is retained as an
explicit stress-test opt-in via `--suite fixed-ratio` or `--suite both`; it is
not part of the default deployment-facing experiment.

With the default realistic suite and three trials, `all-missing` is 96 runs:
32 minutes of payload time and usually about 1-1.5 hours wall time. `bbr-core`
is 48 runs: 16 minutes of payload and usually about 30-50 minutes wall time.
Adding `--suite both` doubles those totals.

xquic uses HTTP/3 and retains the first server qlog per pair. mvfst tperf uses a
raw QUIC stream; it retains the first pcap per pair because the current adapter
does not expose a compatible server qlog.

BBR names do not establish cross-implementation algorithm equivalence. Record
binary hashes and report xquic-BBR and mvfst-BBR as implementation-specific BBR
variants unless source revisions prove otherwise.

## Transition-matched control

The desired controlled follow-up is `steady2` versus `late10`, with identical
ACK-2 startup and identical timer/reordering rules, diverging only after packet
number 100. It is not generated by this launcher yet: the current client binary
only exposes `fixed2`, `fixed10`, `neqo`, and `chromium`. Treat transition-
matched runs as `-todo-` until the client implements and validates both new
runtime policies. Do not relabel `fixed2` versus `chromium` as that control.

After collection, summarize the realistic-policy and fixed-ratio suites
separately:

```bash
python3 scripts/analyze_sender_mechanism_pilot.py \
  /home/ioio33/QUIC_project/results

python3 scripts/analyze_fixed_ratio_mechanism.py \
  /home/ioio33/QUIC_project/results
```
